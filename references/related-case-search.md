# Related-case search

Use this procedure for the final **相关案例推荐** section. The goal is to recommend cases that are genuinely useful for the next practice session, not merely cases that share a broad industry label.

## 1. Build a case fingerprint

Extract the strongest matching signals from the current case:

- industry and subsector;
- core decision or case type, such as profitability, growth, market entry, pricing, M&A, private-equity diligence, operations, organization, or public sector;
- analytical mechanics, such as market sizing, breakeven, unit economics, capacity, valuation, NPV, or exhibit synthesis;
- candidate skills being tested;
- difficulty, interview format, and any important geography.

A useful recommendation should match at least two meaningful signals, including the industry or the core decision. Do not treat a superficial keyword match as related.

## 2. Search current sources

Search the web at recommendation time; do not rely on a static memorized catalog. Use combinations of the fingerprint terms with queries such as:

- `site:.edu consulting casebook filetype:pdf <industry> <case type>`
- `site:<school domain> consulting club casebook <current year>`
- `consulting practice case <industry> <case type> site:mckinsey.com OR site:bcg.com OR site:bain.com`

Vary `casebook`, `case book`, `case interview`, the industry synonym, and the functional problem. Search exact candidate titles when verifying them.

Prioritize sources in this order:

1. An official university or business-school consulting club page, or a casebook linked by that page.
2. An official consulting-firm practice case.
3. A reputable interview-preparation publisher when official sources do not provide enough coverage.
4. A user-provided local collection when the user asks to include it and the files are accessible.

Prefer editions from the latest five academic years. Use an older case when it is a distinctly better match or a recognized classic, and state its year so the user can judge dated assumptions. Avoid anonymous mirrors, document-sharing uploads, and search-result snippets when an authoritative source is available.

## 3. Verify before recommending

For every case, verify as many of these fields as the source permits:

- exact case title;
- school, consulting club, firm, or publisher;
- casebook edition and year;
- page number or stable section locator;
- industry and problem type;
- a direct, usable page or PDF link.

Open the source rather than trusting a search snippet. Confirm that the title actually appears in the casebook or official index and that the material is substantial enough to practise. Exclude the source case itself and deduplicate cases republished in multiple books.

Never fabricate a title, year, page, or URL. If fewer than three recommendations can be verified, return fewer and state the coverage gap instead of padding the list.

## 4. Rank for learning value

Balance closeness and variety. A strong set usually contains:

- the closest overall analogue;
- the same industry with a different business question;
- the same analytical problem in a different industry;
- an optional harder or adjacent case that stretches a specific skill.

Rank primarily by problem structure and industry/subsector, then by analytical mechanics and difficulty. Use recency as a tiebreaker, not as a substitute for relevance.

## 5. Present compactly

For each recommendation give:

`案例名 — 来源/年份（页码，如可核验） | 相似点 | 新的训练价值 | 链接`

Add a short source-quality note only when the link is unofficial or the edition is materially dated. Cite the page supporting each recommendation. Keep the section to 3-5 cases unless the user requests a broader practice plan.
